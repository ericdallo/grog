# AGENTS

- grog: a home voice assistant. A monorepo, see README.md:
  - `brain/`: grog itself (`grog serve`) and the `grog` CLI, which also runs its hands (`grog hands`, `hands.clj`, tools in `machine.clj`), a Babashka app (`bb.edn`, `src/grog`, `test/grog`, `resources/grog`). Its HTTP API is in `api.clj` (JSON keys in lowerCamelCase, both ways; brain/README.md's HTTP API table lists the routes), turns in `assistant.clj`, what it's up to for whoever watches in `events.clj`, what can be asked of it besides answering (restarting, the mic, the volume...) in `actions.clj`, what it asks of grog-voice in `voice.clj`, updating itself in `update.clj` (and `updater.clj`: `grog updater`, run as root by the module's grog-update service, which builds and switches the system), the user's computers it acts on in `computers.clj` (over SSH, to its hands there: `resources/grog/computer.sh`, a bash script needing nothing installed, which grog serves while pairing and the computer keeps, where its policy decides what grog may do; tested from Clojure, with fakes of what it runs, in `computer_sh_test.clj`), pairing them in `pairing.clj`, the server and its background tasks in `server.clj`.
  - `voice/`: grog-voice, its ears and mouth (Python: `grog_voice`, `tests`). `ears.py`: mic → VAD (`endpoint.py`) → speech-to-text (`speech.py`) → wake word (`wake.py`, matched by sound on the transcript); while someone talks, a second Parakeet in a process of its own (`worker.py`, stopped with SIGSTOP while the end is transcribed) transcribes what they said so far over and over (partials, `partialMs`): to hear grog's name before they're done, and to show their words. `mouth.py`: grog's answer (`grog.py`, server-sent events: text, tool) → text-to-speech (`speech.py`: Pocket TTS on OpenVINO, in a cloned voice, streaming, what it reads and Portuguese numbers spelled out in `pocket.py`, its ONNX graphs and voices made by `tools/export_pocket.py` (with torch, outside grog-voice); or Supertonic 3, `supertonic.py`; or Piper, `tts.engine`) → speaker, with earcons (`sounds.py`). `loop.py` wires them, a turn at a time. It tells grog what it's doing (`reporter.py`, `POST /v1/voice`), which answers with its name (the wake word) and whether it shows what's said (`skin.captions`): only then does grog-voice tell it what it heard for grog, never what anyone else said. And it takes what grog asks of it (`commands.py`, `GET /v1/voice/commands`): to listen now, to stop answering, its mic on or off.
  - `skin/`: its skin, a page showing what grog is up to (`web/`: plain HTML, CSS and JS, no build, no dependencies; `view.js` holds the logic, pure and tested with `node --test`: what grog does, which face it makes and how it reacts; `skin.js` and `face.js`, grog's face, whose poses are in `skin.css`, only draw), watching `GET /v1/events` (`brain/src/grog/events.clj`), served by grog (`skin.dir`); and `kiosk.js`, the fullscreen window (GJS, GTK 4, WebKitGTK 6). It shares a small CPU with grog-voice: animate transform and opacity only, only while something happens or now and then at rest (blinks), still while someone talks to grog (every frame costs CPU: check `top` on grognix), and never colors (a repaint every frame). Its face closes its eye only when it can't hear; red is for what just went wrong, amber for what needs someone. What's said only reaches it with `skin.captions`.
  - `body/`: what grog runs on, everything Nix, see body/README.md: `packages/` (grog, grog-voice, grog-skin, listed once in `default.nix`; speech models in `voice-models.nix`), `modules/grog.nix` (the NixOS module: `services.grog`, with `.user` whose session runs `.voice`, `.hands` and `.skin`, and `.update`, grog updating itself when asked), `modules/computer.nix` (`services.grog.computer`, `nixosModules.computer`: a computer grog acts on, once paired), `grognix/` (grognix, a PC dedicated to grog: the same on every machine, `nixosModules.grognix`), `install/` (`nix run .#install`: installs grognix on a machine over SSH with nixos-anywhere, erasing a disk), `tests/` (VM tests of the module, of grognix and of its disk, fake OpenAI).
- Tools: `nix develop` has them all (bb, clj-kondo, python3, ruff, node, shellcheck).
- Tests: `make test` (`cd brain && bb test`, which finds every `*_test.clj`; `cd voice && python3 -m unittest discover -s tests`; `cd skin && node --test`). One namespace: `cd brain && bb -cp src:resources:test -e "(require 'clojure.test 'grog.sse-test) (clojure.test/run-tests 'grog.sse-test)"`. One Python module: `cd voice && python3 -m unittest tests.test_loop`.
- Lint: `make lint` (`clj-kondo --lint src test` in `brain/`, `ruff check` and `ruff format --check` in `voice/`, `node --check` in `skin/`), with no errors or warnings. Format Clojure with `clojure-lsp format --filenames <files>` (without them it can hang), Python with `ruff format`. Shell: `nix run --inputs-from . nixpkgs#shellcheck -- body/packages/grog.sh body/install/install.sh brain/resources/grog/*.sh` (the installer's package runs it too, and grog's, on `resources/grog`). Nix: `nix run --inputs-from . nixpkgs#nixpkgs-fmt -- --check flake.nix body`.
- Full validation: `make check` builds the packages, which run the unit tests in the sandbox. `make check-vm` runs the VM tests one at a time (each takes 4 to 7 GB of RAM; `nix flake check -L` runs everything at once; one: `nix build --no-link -L .#checks.x86_64-linux.module`): `body/tests/module.nix` boots a minimal VM with the module (including a voice turn with the real models, watched through `/v1/events`), `body/tests/grognix.nix` boots the whole grognix config (desktop and headless; it reads the skin off the screen with OCR, drawn on the CPU as the VM has no GPU, and `skin.png` in its output is a screenshot of it: look at it after visual changes), both talking to `body/tests/fake-llm.clj`; `body/tests/disk.nix` formats grognix's disk over what an older system left (disko).
- Only Babashka built-in libraries (no `:deps`), so the Nix package is a plain copy of `brain/`.
- grog-voice: dependencies from nixpkgs only (sherpa-onnx, openvino, sentencepiece, piper-tts without its training extras, pysilero-vad, numpy). Its voice, what was tried for it and how it was measured: plans/voice.md (keep it up to date when the voice changes). Its tests use the standard library only: the model libraries load lazily (`grog_voice/speech.py`), and the loop takes fakes (`tests/fakes.py`). It decides when someone spoke and what they said, never what to answer (that's grog). It must never log or keep what it hears or says: only timings, levels, and exception types (`mouth.where`). Measure speed on grognix itself (a Celeron N5095 without AVX2: int8 and Whisper are slow there), in bursts like real use rather than back-to-back.
- New files must be tracked by git (`git add`) before Nix can see them.
- grognix: nothing particular to one machine goes in the repo (SSH keys, hardware, disks, time zone, Wi-Fi): each keeps it in its own /etc/nixos (`machine.nix`, `facter.json`), written by the installer. Never run the installer (`make install-grognix`: it erases a disk), `make deploy` or `make login` without the user asking. `make build` and `make vm` build a made-up one (`nixosConfigurations.example`, `body/grognix/example.nix`). `make deploy` (`SERVER`, `NIX_SSHOPTS` for ssh options) builds the server's own /etc/nixos with this checkout as grog, and refuses machines without one. Preview risky changes with `nixos-rebuild dry-activate` first. Every grognix runs the nixpkgs in this `flake.lock`: bump it on purpose with `nix flake update`.
- Providers: the contract is in `brain/src/grog/provider.clj`; OpenAI is the only one. Its ChatGPT subscription support (`brain/src/grog/providers/openai/oauth.clj`, `subscription.clj`, and `quota.clj`, how much of its limits is used) is ported from ECA's (`src/eca/llm_providers/openai.clj` and `src/eca/features/quota.clj` in https://github.com/editor-code-assistant/eca): check it there when the Codex backend changes. What an API key spends comes from `providers.openai.prices`: keep them in line with OpenAI's for the default model.
- Settings: grog's defaults in `brain/src/grog/config.clj`, validated at startup (`config/problems`, plus each provider's `:validate`, through `grog.validation`); grog-voice's in `voice/grog_voice/config.py`. Document new ones in the Settings tables of brain/README.md and voice/README.md, and API changes in brain/README.md's HTTP API table.
- Docs: README.md only shows the basics; each part's own README.md (`brain/`, `voice/`, `skin/`, `body/`) has the rest, short and plain. `images/parts.png` is the diagram of the parts: redraw it when they change. `images/logo.svg` is grog's face listening, on its listening color. Both take the skin's palette (`skin/web/skin.css`): redraw them when it changes.
- All text (CLI, prompts, errors, code, comments, docs) is English. The assistant answers in the user's language unless the `language` setting says otherwise.
- The assistant's name is the `name` setting ("grog" by default): never hardcode it elsewhere. The system prompt is the Selmer template `brain/resources/grog/system-prompt.md`.
- Never put secrets in Nix or in the settings: API keys live in the service's environment (`/etc/grog/secrets.env` on NixOS); subscription tokens in the state directory (`auth.json`). Never log what users say.
- Style: small pure functions; Clojure private functions with `^:private`, never `defn-`; no section comments dividing code; clojure.test against fake HTTP servers (`brain/test/grog/test_helpers.clj`) instead of real APIs; Nix with 2-space indent and lowerCamelCase settings keys.
